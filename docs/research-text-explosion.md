# 文字大爆炸 · 真实用户需求研究

> 状态：**需求已验证 + 方案已实现**（见第六、七节，设计详见 `docs/design-cjk-word-selection.md`）
> 日期：2025-08-08
> 目的：为 Jotpad「文字大爆炸」功能收集真实用户需求，先验证需求真伪与优先级，再进入设计。
>
> ⚠️ **核心结论**：经多源验证，「文字大爆炸」作为大功能**不成立**（移动端遗留范式，桌面无需求）；但其底层的「中文双击选词不准」是**真实微痛点**。方案已从「大爆炸浮层」窄化为「CJK 词边界选词优化」。
> 第一至五节为早期研究留档，第六节为验证结论，第七节为修订后的执行方向。

---

## 一、什么是「文字大爆炸」

「文字大爆炸」是中文市场特有的功能概念，命名源自 **锤子科技 Smartisan OS 的 Big Bang**：

> 长按文本 → 文字「爆炸」成可单独点选的词块 → 多选复制 / 搜索 / 翻译 / 删除。

它区别于普通「多选」的核心价值，集中体现在**无空格的中文文本**上——通过自动分词给出词边界，让「挑几个词出来复制」从「光标反复定位」变成「点几下」。

## 三、实测收集到的真实用户痛点

### 来源 1：App Store 评论（一手原文摘录）

**A. 跨应用复制 / 搬运的摩擦**（与「大爆炸」最相关）
> "love being able to write in Markdown and **copy and paste out to other applications** like Confluence" — Bear 1★

- 用户频繁要把文本「搬」到别处，当前复制→粘贴是整段或靠鼠标拖选，**缺少「挑出若干词 / 句」再复制的快捷路径**。

**B. 导航 / 大纲 / 跳转是高频刚需**（iA Writer 多条 1★-4★ 集中在这）
> "No table of contents… Without a table of contents I can't use the app." — iA Writer 1★
> "sub title outline that can **click on** like the…" — iA Writer 4★
> "outline. It turns all my writing into one search" — iA Writer 5★（把它当杀手锏）

- 启示：「大爆炸」应能从拆开的词 / 句**直接跳转或锚定**，而不只是复制。

**C. 误操作 / 安全焦虑**
> "IT DOESN'T HAVE A UNDO FEATURE.. all my work GONE!!" — Bear 4★

- 大爆炸涉及「拆词→删除 / 重排」，**必须可撤销、绝不破坏原文**。

**D. 反对臃肿**
> "getting more and more bloated and difficult to use" — Bear 2★

- Jotpad 是极简记事本，大爆炸**必须轻量、按需触发、不挤占主界面**。

### 来源 2：Hacker News

- 命中 **Smartisan OS Big Bang**（`item:9318193`）—— 这正是「文字大爆炸」的命名起源。
- 文本选择 / 编辑 bug 在 web 编辑器评论中被反复吐槽（`38117528` 等），说明**原生流畅的选择体验是稀缺品**。

## 四、「文字大爆炸」究竟解决什么（需求本质）

基于以上证据 + 中文产品语境，剥离营销话术，它真正回应的是 **4 个互不相同但都被忽视的需求**：

| # | 真实需求 | 触发场景 | 当前痛点 |
|---|---------|---------|---------|
| 1 | **非连续多选** | 从一段话里挑「几个不挨着的词」复制 | 鼠标只能选连续区段，要复制多次 |
| 2 | **无空格文本的自动分词**（中文核心） | 复制中文里的某个词 / 短语 | 中文无词边界，光标定位 + 双击选词常选偏 |
| 3 | **快速重排 / 删改** | 改写句子、删冗余词 | 逐个删除、剪切粘贴来回切换 |
| 4 | **选中即操作**（搜索 / 翻译 / 复制） | 看到不认识或要用的词 | 选完还要右键找菜单 |

> ⚠️ 第 2 点（中文分词）是「大爆炸」区别于普通多选的**核心技术难点**，也是它在中文市场才有意义的原因——Jotpad 作为中文用户为主的记事本，这恰好是契合点。

## 五、给 Jotpad 的初步方案方向（待讨论）

考虑到 Bear 用户「别臃肿」的强烈反馈 + Jotpad 极简定位，倾向**轻量级、按需唤出**的方案，而非常驻面板。

### 交互雏形

1. **唤出**：选中一段文本 → 右键菜单 / 快捷键 → 进入「大爆炸」模式（浮层 / 模态，不污染主编辑区）
2. **拆分**：按「词 / 句 / 字」三档粒度切分（中文用 jieba 分词，英文按空格 + 标点）
3. **多选**：点选任意数量的词块（高亮累加），支持范围扫选
4. **动作**：复制选中 / 删除并回填 / 全选 / 反选 / 搜索 / 翻译（后两者可后续接）
5. **安全**：纯只读视图 + 撤销栈保护，回应「误删焦虑」

### 待拍板的关键取舍

- **① 触发方式**：选中后唤起 vs. 长按（桌面端无长按，建议快捷键 `Cmd/Ctrl+Shift+B` 或右键菜单）
- **② 分词引擎**：引入 `jieba-wasm`（~数百 KB，浏览器端）还是只做「字 / 句」两档避免依赖？
- **③ 范围**：先做「多选复制」（最小可用）还是一步到位含「删改回填」？

## 六、需求验证（假设检验）

### 验证方法
用「假设检验」逐层取证，区分三个命题：①「大爆炸」功能本身是否被需要；② 底层「中文选词难」痛点是否真实；③ 该范式能否迁移到桌面。

### 证据 1：「文字大爆炸」功能本身 —— ❌ 无需求、已死

| 信号 | 数据 | 判读 |
|------|------|------|
| GitHub 实现 | 仅 **5 个仿锤子项目**（iOS SDK / 油猴 / 网页 / Android / Linux OCR），全是 2016–2020 仿制，星标合计 **~50**，全部停滞 | 有人好奇复刻，无人持续维护 |
| Hacker News | 唯一帖 **2 分 / 0 评论**（`item:13069875`） | 技术圈完全无感 |
| 现代 web / 桌面重制 | "text explosion chrome extension" 等 = **0 结果** | 概念未迁移到桌面 |
| App Store 中文写作 App | ~20 款 App 评论中**零提及**「选词 / 复制 / 大爆炸」 | 当前用户根本不提这个需求 |

> 锤子科技 2019 年已倒闭，Big Bang 作为移动端「长按炸词」的范式**没有活下来**。

### 证据 2：底层痛点「中文选词难」—— ✅ 真实存在

需求未必叫「大爆炸」，但底下的痛是真的：

- **CodeMirror（Jotpad 正在用的编辑器）**有 issue：`EditorView.moveByGroup does not respect CJK-language word boundaries` —— 即**双击 / 移动光标选中文，选的是整段而非一个词**，这是 Jotpad 当前就有的问题。
- **VS Code** 有明确 feature request：`Treat the Chinese text as a Chinese sequence`（👍23）。
- CJK 词边界选择是编辑器工程圈公认难题。

### 证据 3：桌面迁移性 —— ❌ 范式错配

这是**最致命的一点**：大爆炸是为**手指（不精确）**设计的。桌面有鼠标，已经能用：

- 双击选词、三击选段
- Shift+点击 扩展选区
- Alt+拖拽 列选

桌面端「选几个不连续的词一起复制」确实仍难（macOS 文本编辑器普遍不支持任意词非连续多选），**但搜索显示这块几乎没有自发需求**——是潜在需求，不是迫切需求。

### 判定

| 命题 | 判定 | 信心 |
|------|------|------|
| 「文字大爆炸」作为大功能是真实迫切需求 | **❌ 不成立** | 高（多源一致负信号） |
| 「中文双击选词不准」是真实痛点 | **✅ 成立** | 高（CodeMirror / VS Code 均有证） |
| 「桌面端多选不连续词复制」有迫切需求 | ⚠️ 潜在但未证 | 中（无自发需求证据） |

**一句话**：用户不会为了「大爆炸」而来，但**双击选中一个中文词却选了一大埚**——这个 Jotpad 当前就有的体验缺陷，是真该修的。

## 七、修订后的执行方向

基于验证，**砍掉原「大爆炸浮层 + 分词 + 多选 + 重排」方案**，换成**一个高 ROI 的小修复**：

> **CJK 词边界感知的选词**：双击中文时，用分词结果选「一个词」而非「整段连续中文」。

### 为什么是这个

- **成本**：挂一个 CodeMirror 双击选区扩展（jieba-wasm 或轻量分词），约半天
- **收益**：直接修掉 CodeMirror 已知 CJK 缺陷，所有中文用户受益
- **不臃肿**：无新 UI、无浮层、无新交互，完全符合 Bear 用户「别臃肿」的诉求

### 暂不做的（保留为观察项）

- ❌ 「大爆炸」浮层 / 多选 / 重排 UI —— 无需求证据
- ⚠️ 「多选不连续词复制」—— 潜在需求，待出现自发反馈再做
